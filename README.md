# ERP System — البنية حسب الأقسام

كل قسم مستقل بملفاته الخاصة، والروابط بين الأقسام تتم **عبر طبقات الخدمات فقط**
(لا استيراد لجداول قسم من داخل قسم آخر). نقطة التجميع الوحيدة هي `backend/main.py`.

## الهيكل

```
backend/
├── main.py                  ← نقطة الدخول: يجمع راوترات كل الأقسام تحت /api/v1
├── requirements.txt
├── core/                    ← مشترك بين كل الأقسام (إعدادات/قاعدة بيانات/استجابة موحّدة)
│   ├── config.py            (Settings + get_current_user JWT + module_deps)
│   ├── database.py          (SQLAlchemy Base + get_db)
│   └── schemas.py           (ApiResponse + PageParams)
└── modules/
    ├── accounting/  🧮 المحاسبة     → /api/v1/accounting/...
    │   ├── models.py    (دليل الحسابات، قيود اليومية، أطراف القيد)
    │   ├── schemas.py   ├── services.py   └── router.py
    ├── inventory/  📦 المخازن       → /api/v1/inventory/...
    │   └── نفس الملفات (أصناف، مخازن، حركات، تقرير الرصيد)
    ├── sales/  💰 المبيعات          → /api/v1/sales/...
    │   └── (عملاء، فواتير بيع، مدفوعات)
    ├── purchasing/  🛒 المشتريات    → /api/v1/purchasing/...
    │   └── (موردون، فواتير شراء، مدفوعات)
    └── hr/  👥 الموارد البشرية      → /api/v1/hr/...
        └── (موظفون، تصفية رواتب + قيد محاسبي تلقائي)
```

## قواعد الربط بين الأقسام (معتمدة ومُختبرة)

1. **المحاسبة هي المركز**: لا تستورد أي شيء من الأقسام الأخرى.
2. بقية الأقسام تستورد `accounting.services` فقط لتوليد القيود التلقائية،
   مع تسجيل `source_module` و `source_ref` ليمكن تتبع كل قيد إلى مستنده الأصلي
   (`GET /api/v1/accounting/journal-entries?source_ref=INV-SALE-...`).
3. المبيعات/المشتريات تستدعي `inventory.services.post_movement` للخصم/الإضافة؛
   حركة المخزون بدورها تولّد قيد المخزون المحاسبي.
4. الروابط المحاسبية (حساب المخزون، الإيرادات، الموردون...) هي **حقول Integer منطقية**
   بدون ForeignKey عابر للأقسام، حتى يظل كل قسم قابلًا للتفكيك/الاستقلال.
5. كل قسم يملك `router.py` مستقلًا بمسار خاص ونقطة `/health` خاصة به.

## التكامل الاختباري المتسلسل

```
فاتورة بيع ⇒ حركة صادر مخزني ⇒ قيد مخزون محاسبي ⇒ قيد إيراد/عميل
فاتورة شراء ⇒ حركة وارد مخزني ⇒ قيد مخزون محاسبي ⇒ قيد مورد/ضريبة
راتب موظف  ⇒ قيد مصروف رواتب مقابل الصندوق
```
النتيجة: ميزان المراجعة متوازن دائمًا (مدين = دائن) — مُتحقق آليًا في الاختبارات.

## التشغيل

```bash
cd <جذر المشروع>
pip install -r backend/requirements.txt
export SECRET_KEY="secret-long-random"        # إلزامي في الإنتاج
uvicorn backend.main:app --reload --port 8000
```

- الوثائق التفاعلية: http://localhost:8000/docs
- الفهرس: http://localhost:8000/  (يعرض قائمة مسارات كل قسم)
- قاعدة البيانات الافتراضية SQLite (`./erp.db`) وتُنشأ جداولها تلقائيًا عند الإقلاع.
